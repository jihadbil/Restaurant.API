# إصلاح مشكلات طبقة النماذج — 17 أكتوبر 2026

عولجت المشكلات الست التي أثبتتها المراجعة، مع الاحتفاظ بتعديلات المشروع الموجودة قبل هذه المهمة.

## التغييرات

| المشكلة | السلوك بعد الإصلاح |
| --- | --- |
| غياب المبلغ المعدود عند إغلاق الوردية | أصبح `CashShiftCloseDto.ActualCash` قابلاً لتمثيل الغياب مع `[Required, Money]`. يرفض HTTP والخدمة القيمة الغائبة، ويبقى الصفر الصريح صالحاً. |
| وجود `null` داخل قائمة عناصر الطلب | تحقق على مستوى DTO، وفحص دفاعي في الخدمة قبل توليد بصمة الدفع أو أي كتابة. يعيد HTTP الرمز 400. |
| نوع طابعة غير معرّف | رفض قيم enum غير المعرّفة في DTOs الإنشاء والتعديل وفي الخدمة. تتحقق الخدمة أيضاً من وجود المحطة. |
| حقول الطلب التي يحددها الخادم | أصبح `OrderNumber` و`UserId` اختياريين في الإدخال للتوافق مع العملاء الحاليين. يتجاهل الخادم القيم المرسلة ويستخدم رقمه المولد والمستخدم الموثق، كما يستبعدهما تحويل AutoMapper. |
| إعدادات طابعة مكررة | ترفض الخدمة تكرار الطابعة الفعلية لنفس النوع والمحطة، مع تجاهل حالة الأحرف والمسافات المحيطة عند المقارنة. يُحفظ الاسم دون المسافات المحيطة، ويضيف EF فهرساً فريداً على `(PrintStationId, PrinterType, PrinterName)` لحماية مسارات الكتابة المتزامنة. |
| احتساب فترة التقارير | الحد الأقصى 366 يوماً شاملاً يومي البداية والنهاية. صُحح أيضاً فلتر نهاية تاريخ الطلبات دون بداية، ليستمر في قراءة الطلبات الأقدم دون تجاوز حدود DateTime. |

تظل مشاركة الطابعة بين أنواع مستندات مختلفة أو محطات مختلفة مسموحة وفق مفتاح التفرّد المحدد.

## ترحيل قاعدة البيانات

الترحيل الجديد: [EnforceUniquePrinterConfigurations](../Restaurant.DataAccess/Migrations/20261017070959_EnforceUniquePrinterConfigurations.cs).

لم يُطبّق الترحيل على قاعدة المطعم خلال هذه المهمة. يطبقه مسار الترحيلات المعتاد عند النشر؛ يشغّل Seeder الحالي الترحيلات عند إقلاع API.

إذا احتوت قاعدة سابقة على إعدادات مكررة، يتوقف الترحيل برسالة واضحة قبل تغيير الفهارس. يحتفظ بالسجلات كي يمكن تحديد الإعداد الصحيح وإزالة التكرار من إعدادات الطابعات ثم إعادة الترحيل. يمكن كشف المجموعات المكررة بهذا الاستعلام للقراءة:

```sql
SELECT PrintStationId, PrinterType,
       UPPER(LTRIM(RTRIM(PrinterName))) AS NormalizedPrinterName,
       COUNT(*) AS DuplicateCount
FROM Printers
GROUP BY PrintStationId, PrinterType, UPPER(LTRIM(RTRIM(PrinterName)))
HAVING COUNT(*) > 1;
```

الرجوع عن الترحيل يزيل قيد التفرّد ويعيد الفهرس السابق دون حذف إعدادات الطابعات.

## التحقق

- نجحت **77/77** من اختبارات الخادم، دون تخطٍ، بما فيها اختبارات SQL Server الفعلية في قواعد مؤقتة مستقلة جرى حذفها بعد الاختبار.
- تغطي الاختبارات الجديدة غياب المبلغ و`null`، وعناصر الطلب الفارغة، وإغفال حقول الخادم ومحاولة تجاوزها، وأنواع الطابعات غير الصحيحة، وتكرار الإنشاء والتعديل، وقيد قاعدة البيانات، وحدود التقارير، وفلتر نهاية تاريخ الطلبات.
- اختُبر ترحيل SQL Server بوجود تكرارات: يرفض الترقية مع الاحتفاظ بالسجلات؛ بعد إزالة التكرار في قاعدة الاختبار ينجح الترحيل ويمنع التكرار، وينجح الرجوع إلى النسخة السابقة مع بقاء الإعداد الصحيح.
- نموذج EF مطابق لآخر Migration.
- نجح بناء تطبيق سطح المكتب مع DTOs المعدلة.

لتكرار اختبارات SQL Server على خادم اختبار يسمح بإنشاء قواعد مؤقتة:

```powershell
$env:RESTAURANT_TEST_SQLSERVER = 'Server=(local);Integrated Security=true;TrustServerCertificate=true'
dotnet test Restaurant.Services.Tests/Restaurant.Services.Tests.csproj
dotnet build Restaurant.Desktop/Restaurant.Desktop.csproj
```
